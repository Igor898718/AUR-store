# AUR Store

Простой графический магазин приложений для [Arch User Repository](https://aur.archlinux.org/):
поиск по базе имён пакетов, просмотр сведений со страницы пакета, установка
и переустановка через собственный AUR helper, а также удаление через pacman.

## Возможности

- загрузка и кеширование списка пакетов AUR (`packages.gz`, около 126 000 имён);
- мгновенный поиск по названиям с ранжированием (точное совпадение → начало имени → подстрока);
- загрузка карточки пакета со страницы `aur.archlinux.org/packages/<name>`:
  версия, описание, upstream-ссылка, лицензия, сопровождающий, голоса,
  популярность, даты и зависимости;
- установленные пакеты помечаются в списке и в карточке, а кнопка
  «Установить» заменяется на «Переустановить»;
- кнопка «Удалить» удаляет выбранный пакет через `pacman -Rns`;
- кнопки «Установить»/«Переустановить» запускают `aur_helper.py` в терминале:
  helper рекурсивно разрешает зависимости, клонирует git-репозитории пакета
  и его AUR-зависимостей и собирает их через Arch Build System (`makepkg -si`);
- режим «Без консоли (pkexec)» выполняет установку и удаление без терминала:
  пароль запрашивается графическим агентом polkit, а вывод показывается в окне;
- кеш базы в `$XDG_CACHE_HOME/aur-store/packages.gz` (обновляется раз в сутки,
  кнопкой «Обновить базу» или по `F5`).

## Состав проекта

| Файл | Назначение |
| --- | --- |
| `main.py` | графический интерфейс на PyQt6 |
| `aur.py` | клиент AUR: загрузка базы, поиск, разбор HTML-страницы пакета |
| `aur_helper.py` | AUR helper: рекурсивные зависимости, клонирование и сборка через `makepkg` |
| `setup.sh` | создание/пересоздание `.venv` и установка зависимостей |
| `images/archicon.png` | иконка приложения |

## Требования

- Python 3.10+;
- PyQt6;
- для сборки пакетов — Arch Linux (или производный дистрибутив), пакеты
  `base-devel` и `git`;
- для режима «Без консоли» — `pkexec` и работающий агент polkit (обычно входят
  в состав графического окружения).

## Установка и запуск

```bash
./setup.sh
source .venv/bin/activate
python main.py
```

Если файл не исполняется, запустите `bash setup.sh`.

`setup.sh` создаёт `.venv` (или пересоздаёт окружение, склонированное с другой
машины), обновляет pip и устанавливает зависимости из `requirements.txt`.
Повторный запуск скрипта безопасен: рабочее окружение переиспользуется.

Если в репозитории остался старый `.venv` с другого компьютера, не запускайте
его вручную: в его `activate` прописаны чужие абсолютные пути, из-за чего
`pip` может обратиться к системному Python и выдать `externally managed
environment`. `setup.sh` определяет такое окружение и пересоздаёт его.

Дополнительные параметры:

```bash
./setup.sh --recreate              # принудительно пересоздать окружение
./setup.sh --venv ~/.venvs/aur     # свой каталог окружения
./setup.sh --python /usr/bin/python3
```

Каталог `.venv` не должен храниться в git. Если он попал в индекс, уберите его
из отслеживания (файлы на диске останутся):

```bash
git rm -r --cached .venv
```

В интерфейсе начните вводить название пакета в строке поиска, выберите его в
списке слева — справа появятся сведения с AUR. Установленные пакеты отмечены
в списке и в карточке, для них показывается кнопка «Переустановить» и
становится доступна кнопка «Удалить».

По умолчанию установка и удаление открывают терминал: там можно ввести пароль
`sudo` и видеть ход сборки. Если включить «Без консоли (pkexec)», действия
запускаются без терминала, пароль запрашивается через polkit, а вывод
показывается в отдельном окне приложения. Для установки в этом режиме helper
запускается от обычного пользователя, а `pacman` внутри `makepkg` — через
`pkexec` (переменная `PACMAN_AUTH`).

Удаление выполняется командой `pacman -Rns --noconfirm`, поэтому вместе с
пакетом удаляются зависимости, которые больше не нужны другим пакетам.

## Использование helper'а отдельно

```bash
# только клонировать (или обновить) репозиторий пакета
python aur_helper.py clone yay

# собрать без установки
python aur_helper.py build yay

# собрать и установить (makepkg -si)
python aur_helper.py install yay

# без интерактивных вопросов makepkg и с пересборкой
python aur_helper.py install --noconfirm --force yay

# установить ещё и все опциональные зависимости
python aur_helper.py install --with-optdeps yay

# не устанавливать checkdepends и передать makepkg --nocheck
python aur_helper.py install --nocheck yay

# отключить рекурсивное разрешение AUR-зависимостей
python aur_helper.py install --no-deps yay

# свой каталог для клонов (по умолчанию ~/.cache/aur-store/build)
python aur_helper.py install --dir ~/aur-build yay
```

Как helper разрешает зависимости:

1. после клонирования читает `depends`, `makedepends`, `checkdepends`
   (и `optdepends` с `--with-optdeps`) через `makepkg --printsrcinfo`;
2. проверяет недостающие зависимости через `pacman -T`;
3. если зависимость есть в официальных репозиториях, её установит сам
   `makepkg -s`;
4. если это AUR-пакет, он рекурсивно собирается и устанавливается до текущего
   пакета; для виртуальных зависимостей провайдер ищется через AUR RPC
   (`by=provides`) и выбирается по голосам/популярности;
5. циклы зависимостей обнаруживаются и выводятся понятной ошибкой.

Helper проверяет имя пакета, не даёт запускать `makepkg` от root и обновляет
уже существующий клон через `git pull --ff-only`.

## Ограничения

- Версии виртуальных зависимостей, выбранных через AUR RPC, не проверяются
  заранее: если ограничение по версии не выполнится, сборка остановится на
  проверке зависимостей `makepkg`.
- Опциональные зависимости по умолчанию не устанавливаются — для этого нужен
  флаг `--with-optdeps`. `checkdepends` можно отключить флагом `--nocheck`.
- Для установки через терминал нужен терминальный эмулятор. Если он не найден
  и режим pkexec выключен, интерфейс покажет вывод helper'а в отдельном окне,
  но интерактивный ввод (пароль `sudo`) в этом режиме недоступен.
- Режим «Без консоли» требует `pkexec` и агент polkit. Если агент не запущен,
  `pkexec` завершится с ошибкой, которая будет видна в окне вывода.
- В режиме без консоли сборочные скрипты, которым нужен интерактивный ввод,
  могут не работать — для таких пакетов используйте режим с терминалом.
- `pacman -Rns` удаляет не только сам пакет, но и ставшие ненужными
  зависимости; подтверждение в интерфейсе предупреждает об этом.
- Список пакетов (`packages.gz`) содержит только имена, поэтому поиск идёт по
  названиям; описания загружаются со страницы выбранного пакета.
